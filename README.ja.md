## 概要

AILEEN は、Windows デスクトップ向けの AI Assistant / AI Agent プロジェクトです。AI 対話、キャラクターシステム、長期記憶、ツール呼び出し、コンピュータ操作、可視化されたキャラクターを、ひとつの対話環境に統合します。Electron アプリケーションとして動作し、UI は素の JavaScript、API キーを扱うリクエストはすべてメインプロセスで実行され、ユーザーデータはローカルにのみ保存されます。

アカウント登録も自前のバックエンドもありません。AILEEN が通信するのは、あなたが設定したモデル・音声・埋め込みの各プロバイダだけです。

現在の主な対象領域：

- **AI 対話とキャラクターシステム** —— キャラクターカード（性格・場面・第一声・会話例）、ペルソナのプロンプト組み立て、TTS / STT、複数プロバイダの LLM 対応（DeepSeek、OpenAI、Moonshot、SiliconFlow、Groq、Zhipu、Qwen、Xiaomi、OpenRouter、Ollama、および互換エンドポイント）。
- **長期記憶とコンテキスト管理** —— 会話の記憶、ローカル知識ベース、そしてシステムプロンプト・キャラクターカード・履歴・記憶・知識・ツール出力をトークン予算つきの1つのリクエストに組み立てる共通コンテキストエンジン。
- **Agent とツール呼び出し** —— 単一 Agent のツールループ。ツールレジストリ、3段階のリスクレベル、明示的な承認フローを備えます。
- **ファイルとコンピュータの操作** —— ファイルの読み書き、ホワイトリスト方式のコマンド実行、git の確認、デスクトップ入力（マウス・キーボード・ウィンドウ切り替え）。すべてワークスペース境界で制限され、操作ごとに承認を求めます。
- **デスクトップ環境との連携** —— フレームなしで既定ではマウスを透過するオーバーレイステージ、および同じキャラクターで遊べる Minecraft とチェス。
- **可視化されたキャラクター** —— 会話の内容に応じてモーションと表情が動く Live2D モデル。
- **画像と視覚** —— 画面キャプチャを視覚対応モデルに渡します。
- **拡張性** —— Agent コアはホスト非依存、ツールレジストリはデータ駆動です。MCP、ブラウザツール、その他の環境は今後の方向性であり、現時点では未実装です。

AILEEN は現在も開発中です。単一用途のチャットクライアントではなく、AI 対話・記憶・Agent 実行・コンピュータ操作のための統合されたデスクトップ環境を目指しています。

> [!NOTE]
> データはすべて手元に残ります。API キー、会話履歴、キャラクターカード、モデルはアップロードされず、アカウント登録も不要です。

## 機能

### AI 対話とキャラクターシステム

すでに利用しているモデルをそのまま使えます —— DeepSeek、OpenAI、Moonshot、SiliconFlow、Groq、Zhipu、Alibaba Bailian、Xiaomi MiMo、OpenRouter。完全にオフラインにしたい場合はローカルの Ollama を利用できます。

各キャラクターは、名前・アイコン・性格・場面・第一声・会話例を持つキャラクターカードで定義されます。同じモデルに2枚のカードを向ければ、2人の異なるキャラクターになります。プロンプトはカードの内容から組み立てられ、カスタムのシステムプロンプトがある場合はそれが優先されます。

**キャラクターカードの生成。** 既存キャラクターの名前を伝えるか、ひと言のヒントを与えると、AILEEN が各フィールドを下書きします。出力はそのまま編集できる草案であり、固定されたプリセットではありません。

### 音声の入力と出力

マイクを押して話しかけると、返答は音声で再生され、そのまま聞き取りが続きます。押しっぱなしのトランシーバーではなく、往復する会話が可能です。タイピング中心の場合は単発の音声入力も使えます。

音声エンジンは4種類で、すでに持っている資格情報をそのまま利用できます：システム音声（オフライン・無料）、OpenAI 互換の任意のエンドポイント、音声クローン用の Fish Audio、そして Xiaomi MiMo。中国語・英語・日本語・スペイン語に対応します。

### 長期記憶と知識ベース

会話は記憶として要約され、ローカルに保存されて、関連するときに呼び出されます。会話ログ全体を繰り返し再生するものではありません。

**知識ベース。** テキスト、Markdown、HTML、JSON、PDF を追加できます。細かく分割してローカルに保存し、現在の会話に関係する部分だけがリクエストに含まれます。PDF の解析は本リポジトリで実装しており、書類を読むために追加の依存は導入していません。

どちらも **設定 → 🧠 記憶と知識ベース** で選ぶ小さな**埋め込みモデル**（OpenAI、SiliconFlow、Alibaba Bailian、Zhipu、ローカルの Ollama、または互換エンドポイント）を使用するため、検索はキーワードではなく**意味**に基づいて行われます。埋め込みモデルを設定しない場合、検索はキーワード一致に退化し、完全にオフラインのまま動作します。

記憶と知識ベースのデータはアプリケーションのデータフォルダに保存され、書き込みできるのはそれらに対応する2つのフォルダだけです。

> [!NOTE]
> 埋め込みモデルのキーは、アプリ内の他のキーと同じ扱いです。画面からは見えません。リクエストはメインプロセスが送信し、レンダラーが受け取るのは「設定済みかどうか」を表す真偽値だけです。

### Agent とツール呼び出し

サイドバーで **🖥 パソコン操作** を有効にします。**入口は通常のチャット欄のまま**で、話しかけ方は変わりません。ツールが必要かどうかを Agent が判断し、実行して結果を報告します。

権限は3段階のリスクレベルで運用されます。読み取りは制限なく行えますが、パソコンに触れる操作は毎回承認を求めます。この要件は**設定からも外せないように意図的に作られています**。

> [!IMPORTANT]
> タスクの実行中、右側のステージは **Agent コントロールダッシュボード**になります：タスク、現在の手順、時刻付きの操作ログ、ツール呼び出し、取得した画面、承認ボタン。ツールのログがチャットの吹き出しに挿入されることはありません。

> [!NOTE]
> キャラクターの人格は保持されます。システムプロンプトの最初の一段は常にキャラクターカードであり、雑談中でも、チェス中でも、デスクトップ操作中でも同じです。人格が失われた場合は、検査によって実行が即座に中止されます。

### パソコン操作

利用できるツールは、ファイルの読み書き、ホワイトリスト方式のコマンド実行、git の確認、画面キャプチャ、マウス操作、キーボード入力、アプリケーションの起動、ウィンドウの切り替えです。タスク完了後は、汎用の完了メッセージではなく、キャラクター自身の口調で結果を報告します。

Agent が触れる範囲は、ワークスペース境界（外側のパスは拒否されます）と上記の承認フローによって制限されます。

### キャラクター表示

任意の Live2D モデル（Cubism 2 / 3 / 4）をキャラクターとして使用できます：待機モーション、呼吸、モーション、表情、そして発話中の口の動き。モデルのフォルダを読み込むか、`model3.json` の URL を貼り付けてください。

> [!TIP]
> モデルの追加は2クリックです：**設定 → 🎀 Live2D モデル設定 → 📁 フォルダから読み込む**。ステージパネルにも同じボタンがあります。

### フローティングステージ

フローティングステージは、キャラクターをデスクトップ上のフレームなし・透過・常に最前面のウィンドウに配置します。**既定でマウスを透過**するため、下にあるウィンドウはクリックを失いません。ハンドルはポインタが近づいたときだけ表示されます。

> [!TIP]
> `Ctrl+Shift+S`（またはメニューの **ステージ → 枠なしステージの表示／非表示**）で切り替えられます。ドラッグ、`−` / `＋` ボタンでのサイズ変更、メニューからのすみへの復帰が可能で、位置とサイズは記憶されます。

### 視覚

任意のウィンドウやモニターのスクリーンショットを、質問と一緒に送信できます。スタックトレースの確認やグラフの確認によく使われます。視覚機能にはマルチモーダルモデルが必要です：`qwen-vl-plus`、`gpt-4o`、`glm-4v`、`MiMo-VL` が動作します。テキスト専用モデルは画像を無視します。

### インタラクティブ環境

**Minecraft。** キャラクターはボットとして Java 版サーバーに参加します。あなたを追いかけ、手動操作を受け付け、サーバーのチャットで発言し、自動返信を有効にすると他のプレイヤーにもその子自身の口調と人格で返答します。

**チェス。** 難易度5段階、白番・黒番の選択、待った、盤面反転、そしてあなたが考える間の局面に対するコメント。

## アーキテクチャと設計

### 設計上の要点

- **カードがプロンプトの唯一の出所です。** 名前・アイコン・性格・場面・第一声・会話例はすべて1枚のカードに由来し、カスタムのシステムプロンプトがある場合は生成されたペルソナより優先されます。
- **人格はすべての場面で共通です。** Minecraft とチェスは、使い捨てのプロンプトを別に用意するのではなく、キャラクターの人格をそのまま再利用します。
- **フローティングステージは既定でマウスを透過します。** この挙動はセルフテストが最初に確認する項目のひとつです。
- **ソースは読めるままに。** 難読化されたベンダーの塊も、隠れたサービスもありません。挙動はすべて本リポジトリから追えます。
- **API キーはレンダラーに渡りません。** モデル・音声・埋め込みプロバイダへのリクエストはメインプロセスが送信し、画面が受け取るのはマスク済みの設定だけです。

### ディレクトリ構成

```
main.js               Electron メインプロセス —— アプリのライフサイクルと配線
preload.js            contextBridge で公開する API
mc-bot.cjs            Minecraft ボット
shared/               メインプロセス・レンダラー・テストで共有するコード
  ipc-guard.cjs       IPC を呼べるのは誰か
  ipc-validate.cjs    何を渡してよいか
  ipc-schemas.cjs     チャンネルごとの検証ルール
  llm.cjs             ストリーミング対話のコア（API キーはメインプロセスから出ません）
  agent-ipc.cjs       Agent のツールがあなたの PC に対して行えること
  embeddings.cjs      埋め込みの計算とオフラインへのフォールバック
  store-ipc.cjs       記憶と知識ベースが書き込める2つのフォルダ
src/
  main/               メインプロセスのモジュール
    self-test.cjs     診断 —— AILEEN_SELFTEST=1 のときだけ実行
    server/           モデルとアイコンを配信するローカル静的サーバー
    storage/          設定と API キーの保存
  agent/              Agent コア：runtime、planner、ツール、権限、executor
  context/            共通コンテキストエンジン（プロンプトの層とトークン予算）
  memory/             長期記憶：抽出、保存、検索、統合
  knowledge/          ローカル知識ベース：解析、分割、検索
  lib/                画面まわり —— state、dom、stage、chat、characters、modals、
                      voice、minecraft、chess、agent-dashboard、agent-ui、i18n
  overlay.*           フローティングステージのウィンドウ
tests/                ユニット / 統合 / E2E（tests/README.md を参照）
```

### モデルとアイコンをローカル HTTP で配信する理由

モデルとアイコンは `file://` ではなく、小さなローカル HTTP サーバー経由で配信しています。これは見た目の都合ではありません。Live2D の WebAssembly とテクスチャは `file://` では読み込めず、これが最も影響の少ない解決策でした。このサーバーは localhost にのみ bind し、あなたの PC の外に出ることはありません。

### インターフェースと言語

**English / 日本語 / 简体中文** に対応しています。部分的な翻訳ではなく、全体が翻訳されています。初期状態は英語で、クリック一つで切り替えられます。

**設定 → 🌐 Language**、またはネイティブメニュー（`Alt`）からいつでも変更できます。**アプリケーションメニュー自体もローカライズされています。**

> [!TIP]
> 4つ目の言語を追加する場合：文言は `src/lib/i18n.js` と言語ごとの JSON ファイルにまとまっており、UI はすべてそこから読み込みます。ファイルを1つ追加し、`LANGS` に1行足せば利用できるようになります。プルリクエストを歓迎します。

## 開発

```bash
git clone https://github.com/haixu8396-png/aileen-desktop.git
cd aileen-desktop
npm install
npm start        # 画面をビルドして起動
```

Node.js 18 以上が必要です。初回実行時に Electron をダウンロードします。回線が遅い場合は先に `ELECTRON_MIRROR` をミラーへ向けてください。Windows では `install.bat` をダブルクリックしても構いません。

```bash
npm run dist     # インストーラー + ポータブル版を release/ に出力
npm test         # ユニットテスト
npm run lint     # 構文チェックとプロジェクト固有の境界ルール
```

Windows では `build-installer.bat` が `npm run dist` と同じ処理を行います。

## 謝辞

### その肩の上に

**[moeru-ai/Airi](https://github.com/moeru-ai/airi)** に敬意を表します —— AILEEN はこれなしには存在しませんでした。「オープンソースの AI コンパニオン」を願望ではなく現実のものとして示してくれたプロジェクトであり、このリポジトリは公然と Airi に倣っています：README の構成、習慣、そしてバーチャルキャラクターを丁寧に作る価値があるという確信。まだ Airi を見ていない方も、あのスターの数には十分な理由があります。

そして、その発想の源は **[Neuro-sama](https://www.youtube.com/channel/UCLHmLrj4pHHg3-iBJn_CqxA)** です。声と記憶と人格を持ったキャラクターが、ソフトを見ていることを忘れさせる —— それを示した AI VTuber です。それが基準であり、AILEEN はその方向への小規模な試みにすぎず、まだ遠く及びません。

### 使わせてもらっているもの

- [mineflayer](https://github.com/PrismarineJS/mineflayer) と [mineflayer-pathfinder](https://github.com/PrismarineJS/mineflayer-pathfinder)：手を持たないキャラクターが Minecraft の世界であなたを追いかけ、みんなと同じようにフェンスで引っかかるのは、これらがあるからです。PrismarineJS は JavaScript 版 Minecraft エコシステムを長年にわたり維持しています。
- [js-chess-engine](https://github.com/josefjadrny/js-chess-engine)：依存ゼロでありながら、実際に探索を行うチェスエンジンです。これほど小さいことをいまだに疑っていますが、毎回勝っています。
- [oh-my-live2d](https://github.com/oh-my-live2d/oh-my-live2d)：ビルドシステムと格闘せずに Live2D をページに載せられます。Cubism 2/3/4 対応もここから来ています。
- [DOMPurify](https://github.com/cure53/DOMPurify)：モデルの出力を安全に Markdown として描画できるのは、これのおかげです。
- [minecraft-protocol](https://github.com/PrismarineJS/node-minecraft-protocol) —— BSD-3-Clause。Minecraft のワイヤプロトコルを代わりに扱ってくれます。

Live2D Cubism Core ランタイムには Live2D 社のライセンスが適用されます。追加した各 Live2D モデルにもそれぞれの規約があります。原作者の条件を尊重してください —— 特に配信で使用する場合は注意が必要です。
